## Installed Excel acceptance

Microsoft Excel file/product version `16.0.20430.20092`, Windows, controlled through the native application on 10 October 2026. Fixture was generated by the actual `StreamingCsvExporter`; all data is synthetic. Harmless inputs cover `=1+1`, `+1+1`, `-1+1`, `@SUM(1,1)`, whitespace/tab/NBSP/BOM/zero-width prefixes and full-width equals. No DDE, links, commands or real financial data.

Opened UTF-8 CSV in Excel's Text Import Wizard: Delimited, comma on, tab off, quote qualifier `"`; content column General and money column Text. The cell `Đêm Nhạc Mùa Thu — Vé đã soát` retained exact Vietnamese; money `9007199254740993` retained all digits. `SUMPRODUCT(--ISFORMULA(B3:B12))` returned **0**. Saved a separate copy as **CSV UTF-8 (Comma delimited)**, closed it, reopened with the same import settings and evaluated a newly entered formula: result **0** again; Vietnamese and the large money string still matched. This proves RPT-03/04 for this version and import workflow, not every spreadsheet/version.

The legacy Text Import Wizard split the embedded multiline fixture; therefore it is not recommended for fields containing newlines. Use Excel **Data → From Text/CSV**, UTF-8, comma, and set money/identifier columns to **Text**. Product help states this import policy. Exact serialized CSV bytes and quote/newline preservation are covered separately by exporter tests. Spreadsheet auto-conversion under General is not a money precision guarantee; Text is required. Synthetic original/round-trip files and private logs remain outside Git.

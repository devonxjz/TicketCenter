Problem

The refund HTTP surface is fragmented across six micro-servlets bouncing between two static helper modules to extract actors and format errors.

Solution

Deepen into a unified RefundManagementServlet that owns route dispatching, actor extraction, and error translation behind a single entry seam.

Architectural Wins

  • ✓ locality: routing and security live in one module
  • ✓ leverage: one test surface for all refund endpoints
  • ✓ interface shrinks: delete 8 shallow classes
  • ✓ no static request attribute bouncing

Problem

EventManagementWeb is a 250-line static procedure mixing ad-hoc string path splitting, untyped action dispatching, and multipart forward delegation.

Solution

Deepen into an EventManagementDispatcher module that encapsulates typed sub-route dispatching behind a clean seam, with co-located guards.

Architectural Wins

  • ✓ locality: zone pricing and cover validations don't interleave
  • ✓ leverage: operations tested without 200-line monolithic harness
  • ✓ depth: clean internal seams replace string array hacks
  • ✓ eliminates untyped action string switching

Problem

Six domain caches duplicate identical fail-open try-catch blocks, connection borrowing, and TTL handling.

Solution

Deepen a generic RedisCachedProjection adapter that encapsulates connection borrowing, error suppression, and TTL policies behind a small get/put/evict interface.

Architectural Wins

  • ✓ leverage: one fail-open policy across all domains
  • ✓ locality: connection timeouts and logging handled once
  • ✓ deletion test: removes ~200 lines of duplicated boilerplate
  • ✓ testability: trivial substitution with in-memory adapter
Candidate 4

Consolidate the CheckIn Web Cluster

Worth exploring in-process
Involved Files
  • vn.ticketscenter.fulfillment.checkin.controller.CheckInWeb
  • vn.ticketscenter.fulfillment.checkin.controller.TicketCheckInServlet
  • vn.ticketscenter.fulfillment.checkin.controller.EventCheckInLogsServlet

  • vn.ticketscenter.fulfillment.checkin.controller.CheckInScannerServlet
  • vn.ticketscenter.fulfillment.checkin.controller.CheckInWindowServlet

Problem

Five micro-servlets act as shallow pass-throughs to a static CheckInWeb helper, spreading check-in HTTP logic across seven files.

Solution

Consolidate into a single CheckInServlet module with structured top-down execution order.

Architectural Wins

  • ✓ locality: entire check-in HTTP flow in one place
  • ✓ interface shrinks: eliminates 5 servlet registrations
  • ✓ deletes 5 pass-through classes
  • ✓ consistent error handling across scanner and logs
Top Recommendation

Candidate 1: Collapse the Refund Web Pipeline

The refund subsystem has the highest fragmentation in the repository: 6 shallow servlets, 1 route filter, and 2 static helper classes just to dispatch refund requests. Collapsing this into a unified RefundManagementServlet achieves maximum locality, cuts over 150 lines of glue code, and establishes a single, clear test surface for the entire refund feature.
